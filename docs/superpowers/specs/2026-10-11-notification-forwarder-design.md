# Windows 通知转发工具设计

日期：2026-10-11

## 目标与已确认范围

用户下班后让 Windows 电脑继续运行 AI 开发任务，希望在手机上的飞书、钉钉或企业微信收到通知和已有结果内容，不必远程登录电脑。工具也可分发给其他人，每个人独立安装、配置自己的接收渠道。

采用本地 Windows APP，电脑直接向平台发送消息，不建设运营云服务。手机仅接收消息，不提供回复、远程控制或权限审批。核心先完成通用 Windows 通知转发，Agent 接入为可选增强，预留扩展入口。

## 产品行为

首次运行引导用户授权读取 Windows 通知、选择应用、配置接收渠道、发送测试消息和设置转发时间。默认不转发全部应用，用户明确勾选来源。可选登录后自动启动；主窗口关闭后保持托盘运行，托盘提供打开、暂停和退出操作。

四个页面：

1. 首页：监听权限与运行状态、当前转发时段、最近发送结果、暂停开关。
2. 通知来源：应用选择、已捕获文本预览、关键词过滤；Agent 接入作为独立可选来源。
3. 接收渠道：添加、编辑、启停多个渠道，填写凭据和发送测试消息。
4. 转发规则与记录：星期和时间段配置、发送历史、渠道失败原因。

普通消息包含来源应用、原标题、原正文、通知时间以及可配置的电脑名称。保留来源提供的文本，不根据普通通知自行推断任务成功，不调用模型生成摘要。通知正文可能只是摘要，转发内容不等于完整会话。

## 时间规则

支持全天转发、按时间段转发、暂停转发。时间段使用电脑本地时区，每条规则包含星期和开始、结束时间，支持多条规则；命中任意规则即可转发。开始时间包含、结束时间不包含。跨午夜规则的星期指开始日，例如周五 18:30—次日 09:00 包括周六早晨。全天使用独立选项，开始和结束相同的普通时间段视为无效。

示例模板：周一至周五 18:30—次日 09:00，周六、周日全天；仅为可编辑模板，安装后用户保存选择才生效。

时间段外的消息不加入发送队列，不积攒到下班后补发。普通历史记录如显示被过滤事件，应明确标注未转发。处理恢复或启动时，只考虑实际通知时间符合规则且仍未过期的消息；第一次授权时现有通知建立基线，不批量发送历史消息。

每次发送或重试前再次检查当前时段及暂停状态。窗口外暂停重试；队列消息超过 24 小时后标记过期，不再发送。时间或时区变化后重新计算状态，不产生历史补发。

## 架构与数据流

通知来源适配器 → 统一消息 → 来源/关键词过滤 → 时间规则 → 持久化待发队列 → 渠道适配器。

- Windows 来源通过官方 UserNotificationListener 接口读取通知标识、来源、时间和文本元素，适配通知布局；没有正文时允许仅转发标题。无可用文本时记录原因并跳过。
- Agent 来源将 Hook、插件事件转换为相同消息格式。通用入口计划提供命令行及仅本机访问、带令牌验证的 HTTP 接口，不向局域网开放。首轮实现顺序由后续实施计划确定。
- 统一消息包含内部标识、来源类型、来源应用、原标题/正文、发生时间以及可选的项目、会话和事件状态。
- 规则模块独立于消息来源和渠道，可进行时间边界测试。
- 发送模块为每条消息的每个渠道独立维护状态。部分渠道失败时，仅重试失败渠道。
- 本地存储保存配置、处理标识、待发消息和发送记录；渠道凭据使用 Windows 用户范围的系统保护机制保存，界面与日志不回显完整密钥。

来源适配器不得依赖具体接收平台。渠道适配器不得依赖具体 Agent。添加工具或平台时不修改时间判断和队列规则。

## 重复通知与消息长度

同一 Windows 通知标识、相同内容不重复转发；同一标识内容更新时，尚未发送的队列项更新为最新内容。已发送后的内容更新可发送一次新的更新消息。启动基线与已处理标识持久化，避免每次重启重新发送。

不同来源之间只有可靠的关联标识时才自动合并，不能仅凭相近时间和相似标题丢弃消息。Agent 一轮响应结束、进程退出、明确的任务成功、错误和等待输入分别标注，未知状态不映射为成功。

各渠道根据平台限制处理长正文：按顺序分段并标注分段序号，设置合理的总长度上限；截断时明确提示。仅发送本机文件路径不构成手机可访问的产物链接，第一版不提供文件托管。

## 平台接入顺序

先实机验证 ChatGPT、Cursor 的 Windows 通知到飞书群机器人的完整链路。飞书、钉钉、企业微信作为目标渠道；各渠道只有在当前官方接口、账户条件和实测发送都确认后才能标记可用。

飞书以群机器人 Webhook 为初始方案。钉钉官方资料提示群自定义机器人将下线，不能假设新用户均可创建旧 Webhook 机器人；需要核对现行机器人方案。企业微信接入资格、接口和配置流程需要在实施前核对。涉及管理员审批的条件应在渠道配置向导中说明。

Agent 扩展候选包括 Claude Code、OpenCode、Codex CLI、Cursor、Gemini CLI、GitHub Copilot CLI，以及使用命令包装的 Aider。明确区分 ChatGPT 图形界面的通知监听与 Codex CLI 的 notify 接入，不将 CLI 功能推定为桌面客户端功能。

## 锁屏与电源状态

支持电脑锁屏但用户仍登录、电脑保持唤醒且联网时继续工作，这是下班场景的必需验收项。无需抓屏，也不要求通知横幅出现在锁屏界面。源应用实际生成的系统通知、授权和系统策略会影响可读取内容，必须实机验证，不能仅凭文档承诺所有应用在所有锁屏设置下都可靠。

关闭显示器和锁屏与休眠不同。普通休眠、休眠到磁盘、关机和用户注销期间不保证实时执行或发送。恢复后只尝试处理符合规则、未过期且仍可读取的消息，不保证恢复源应用从未生成或已删除的通知。

第一版说明保持电脑唤醒的要求，不自动修改系统电源设置。若某应用锁屏后不生成可读取通知，使用 Agent 事件入口作为增强方案，并明确该应用的兼容性结果。

## 错误处理与隐私

权限拒绝或撤销时显示明确状态与恢复入口。解析单条通知失败不终止监听。网络超时、限流和暂时性服务错误采用有上限的退避重试，最多 5 次重试并遵守时段和 24 小时有效期；凭据错误、配置错误和明确的永久拒绝不自动持续重试。尊重平台的重试等待提示。

超时可能发生在平台已接收消息之后，外部平台不支持幂等时不能承诺绝对不重复，应在记录中体现结果不确定。

提供手动重发操作，仍遵守时间限制；显式测试消息由用户点击触发，可在正常窗口外发送并清楚标为测试。通知正文存储保留 7 天，发送状态保留 30 天，支持清空历史；日志不记录完整凭据。配置导出排除凭据和消息历史。

## 验收与验证

1. 实机读取 ChatGPT 和 Cursor 通知标题、正文与来源，并在飞书手机端确认收到对应文本。
2. Win+L 锁屏后源任务继续执行，新通知在允许时段内发送；验证锁屏内容隐藏设置下的实际表现。
3. 验证通知授权拒绝、撤销及再次授权，确保状态明确。
4. 验证开始/结束边界、跨午夜、星期归属、多规则重叠、暂停以及本地时间变化。
5. 验证时间段外消息不补发，窗口外不自动重试，过期消息不发送。
6. 验证断网恢复、部分渠道失败、凭据失效、限流、程序重启后的待发队列恢复与重复通知处理。
7. 验证源通知仅有标题、不同布局、正文过长、内容更新，以及 Agent 状态不会被错误标为成功。
8. 验证安装、托盘退出、登录启动选项、凭据保护和不含密钥的配置导出。
